Bugs & Issues

dt_hours instrumentation bug (confirmed): In the F2 pair model training, _ts_of reads updated from the story object instead of published, making dt_hours a constant 0 for all pairs. This means the temporal signal feature is entirely broken and must be refixed using published timestamps before any conclusions about the value of temporal signals.

Over-merge bug with embed-cluster: When using --embed-cluster, the system created a single story with 645 coverages, merging unrelated articles. The entity anchor wasn't sufficient to prevent this. Marked as experimental and not recommended for production.

Safra Trump × Papa case: A cluster incorrectly merged stories about Trump tariffs on EU agricultural products with stories about the Pope's death. Both shared entities ("Trump", "Papa") but were about completely different events. This is the canonical test case for the false-equivalence gate.

Factuality score display inconsistency: Some sources have factuality ratings that were set by a single annotator (the project owner). The ratings need validation from 2+ independent models/annotators.

Timezone handling: There were issues with timezone handling in article timestamps, particularly with feeds that don't specify timezone. Tests were added (test_timezones.py).

Google News redirect links from Aos Fatos: The Aos Fatos feed via Google News RSS returns redirect URLs instead of direct links. This is documented but not fully resolved.

Design Decisions

Fixed bias per source (not per article): Unlike Ground.news which rates articles individually, Balanço uses a fixed bias rating per publication from sources.yaml. This is a deliberate decision to avoid AI costs per article, though LLM classification is available opt-in via --llm.

Editorial group deduplication: When calculating bias bars, articles from the same editorial group (e.g., G1 + O Globo + Valor = Grupo Globo) count as 1 voice, not 3. This prevents conglomerates from dominating the bias distribution.

Static site, no backend: The entire output is a static HTML page with a JSON data file. No server, no database in production. GitHub Pages serves it.

Conservative fact-check matching: Uses IDF-weighted term overlap rather than semantic similarity to match fact-checks to stories. This avoids false positives (matching "same topic" instead of "same claim").

Body for machine, short for human: Even when --body fetches full article text, only the description or a short excerpt is shown to the user. Full body is for clustering/matching algorithms only.

Service content filtered out: Lottery, horoscope, weather forecasts, payment calendars are excluded by editorial decision. Weather events with impact (flooding, etc.) are kept.

Foro de Teresina = podcast: Specifically filtered as podcast content, not hard news.

Entity as subject + place is not a "pauta": Geographic locations alone don't constitute a topic/thread. "Mato Grosso" was incorrectly grouping violence in MS, soy farming, and state court stories.

Opinion/longform don't age stories: The updated timestamp of a story uses only hard news coverage; opinion pieces and videos don't make the story appear "fresh".

Gate approach for false equivalences: Two approaches were debated:

Hard gate: Remove pairs where P(same) < threshold. Problem: recall drops to ~0.3
Veto: Only reject pairs where P(same) < ~0.2. Would break bridges like "safra Trump × Papa" without recall cost.
Neither was implemented yet.
Performance Concerns

TF-IDF matrix recomputation: The tfidf_matrix is computed fresh each run. With min_df=1, simplifying would change all cosine similarities and require recalibrating thresholds (0.38/0.62).

O(n²) pairwise comparison: The clustering uses pairwise cosine similarity, which is O(n²) in the number of articles (~440/round). This is acceptable now but may not scale.

Embedding model loading: MiniLM model loading takes significant time on first run. Cached in state/models/ for subsequent runs. ONNX/fastembed backend is lighter than full torch.

HTTP requests: Even with caching and conditional requests, 53 sources × 1 request each = 53 minimum requests per cycle. The 30-minute cron is appropriate but could be tuned.

Body enrichment bottleneck: --body with 40-cap and 2-second delay = up to 80 seconds of serial fetching per round.

UI/UX Items

Atlantic-inspired editorial design: Serif fonts, thin rules, small caps, breathing space. Combined with Ground.news-style bias bar (Left/Center/Right).

Collapsible sections: "Aprofunde-se", "Lá fora", "Outros ângulos desta pauta" use <details> closed by default with counter headers.

Mobile responsive: Pill-style scrollable filters, fixed search bar on mobile.

Deep links: Stories are linkable via ?story=hXXX with stable IDs.

Local analytics only: Usage tracking (?uso=1) stores clicks in localStorage only — no network, no cookies. Export/clear available.

"Leituras da semana": Separate page for longform readings, 2-column layout with thumbnails.

Framing comparison ("Como cada lado intitulou"): Log-odds analysis of terms used by each political side in headlines.

"Quem deu primeiro": Timeline showing which outlet published first, ordered by publication date.

Open Questions

F3: Hard gate vs veto? The pair model (AUC 0.835) doesn't reach P≥0.97/R≥0.80. Hard gate fragments clusters (R~0.3); veto (reject if P(same)<~0.2) would break false bridges without recall cost. Neither implemented.

same vs related boundary: The related class is lexically almost identical to same using only titles. Options: use summaries as signal, verb features, expand F1 to 600 pairs, or accept conservative gate (P0.93/R0.43).

tfidf_matrix simplification: Should min_df=1 be applied? Would change all cosine scores and require threshold recalibration.

Bias/factuality governance: Current ratings are from a single annotator. Need 2+ independent models/annotators and reported agreement metrics.

Newsletter provider: Newsletter feature designed but no email provider chosen yet.

Domain/SEO/Analytics: Site is live on GitHub Pages but lacks custom domain, proper analytics, and SEO optimization.

Legal review: Terms of use, correction/errata policy, evaluation of PL 2338/2023, and republication licensing considerations pending.
